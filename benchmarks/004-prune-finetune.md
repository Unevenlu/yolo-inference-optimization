# 004 - 结构化剪枝 + 微调恢复：一次"失败"得很有价值的实验

**日期**: 2026-10-13

## 目的

用 torch-pruning 对 yolov8n 做结构化通道剪枝（30%），再用小数据微调恢复精度，走完"剪枝 → 精度崩塌 → 微调恢复"的完整流程。

## 数据纪律

coco128 拆成 **96 训练 / 32 留出验证**两个互斥子集：微调只用 96 张训练图，mAP 只在没见过的 32 张上测。注意本实验 mAP 口径与实验 003（全量 coco128）不同，只能内部纵向比较。

## 结果

| 阶段 | 参数量 | GFLOPs | 大小 | mAP50-95 | mAP50 |
|------|--------|--------|------|----------|-------|
| 基线 | 3.16M | 8.86 | 12.2MB | 0.4642 | 0.607 |
| 剪枝 30%（未微调） | **1.81M (-43%)** | **5.59 (-37%)** | 7.06MB | **0.0** | 0.0 |
| + 微调 10 epoch (SGD) | 1.81M | 5.59 | 7.06MB | 0.0002 | - |
| + 微调 20 epoch | 1.81M | 5.59 | 7.06MB | 0.027 | - |
| + 微调 30 epoch | 1.81M | 5.59 | 7.06MB | 0.0135 | - |
| **对照：未剪枝 + 同样微调** | 3.16M | 8.86 | 12.2MB | **0.4438** | - |

**核心现象：一次性剪枝让模型功能彻底崩溃（mAP 归零），小数据微调 30 个 epoch 也几乎无法恢复；而未剪枝的对照组在相同微调配置下精度几乎不变——证明训练管线本身没有问题。**

## 排查过程（本实验最有价值的部分）

面对"崩溃 + 不恢复"，逐层排除了所有结构性嫌疑：

1. **剪枝机制正确性**：在简单网络上，tp 剪枝结果与手工切片参考**逐位相等**（误差 0.0）。
2. **concat 通道对齐**：用 BN 的 gamma 值作"指纹"追踪每个被保留的通道，验证检测头的输入卷积切片索引与 neck 输出保留索引**完全一致**——没有通道错位。
3. **逐层激活统计**：剪枝后所有层特征均值/标准差健康，没有死层。
4. **泛化排除**：微调后在 96 张训练图本身上 mAP 也只有 0.0014——不是过拟合/泛化问题，是模型连训练集都学不回来。
5. **优化器排除**：发现 ultralytics 默认 `optimizer='auto'` 会改用 AdamW 并忽略 `lr0`，改用显式 SGD(lr0=0.01) 后依然不恢复。
6. **崩溃粒度测试**：只剪第一层 50% → mAP 0.162（可接受退化）；全网络剪 5% → mAP 0.001；只定向剪 2 个最大 C2f 块的 30% → mAP 0.002。**崩溃不取决于单层剪多狠，而取决于"同时动的层数"。**

## 结论：为什么会这样

- **跨层复合漂移**：每一层被切掉 10% 通道，输出分布偏移一点，经过 50+ 层复合放大，到检测头时特征已经面目全非（分类置信度从 0.18 掉到 0.0008）。单层剪 50% 网络能扛住，全网各剪 5% 就崩溃。
- **小模型冗余少**：yolov8n 仅 3M 参数，通道几乎没有冗余；同样的剪枝比例在 yolov8m 上损伤会小得多。
- **幅度重要性 ≠ 精度贡献**：L2 范数小的通道可能仍对最终精度关键，更优的标准是 BN-scale、Taylor 梯度等。
- **恢复的本质是重新学习**：崩溃后的模型不是"受损的好模型"而是"结构更小的随机水平模型"，恢复需要**真实数据量 + 足够步数**，96 张图 × 60 步远远不够。Torch-Pruning 官方 yolov8 示例能恢复，靠的是：迭代式剪枝（16 步 × 4.4%，永不彻底崩溃）+ 每步 10 epoch × 共 160 epoch + **在训练集上评估**（含记忆成分）。

## 生产级剪枝配方（本实验得出的教训）

1. 迭代式剪枝：小比例多次剪（每步 ≤5%），每步之间充分微调
2. 恢复训练用完整训练集（或至少数千张），不是 96 张
3. 重要性感知优先考虑 BN-scale / Taylor，而非纯幅度
4. 剪后 BN 统计失效，恢复训练的前几十个 batch 必须先让 BN 统计重新适应

## 踩坑记录（工程细节）

| 坑 | 解法 |
|----|------|
| ultralytics 加载的模型 `requires_grad=False`，torch-pruning 依赖 autograd 追踪，依赖图只捕获到 1/64 层 | 剪枝前 `requires_grad_(True)`（保持 eval 模式避免随机输入污染 BN） |
| C2f 的 `chunk` 操作依赖图无法追踪（IndexError） | 按官方示例替换为等价 C2f_v2（cv1 拆 cv0/cv1），并记得拷贝 `f/i/type` 等模块元数据 |
| torch-pruning 1.6.x 图构建与 ultralytics 不兼容 | 固定 `torch-pruning==1.3.5` |
| `model.train()` 会按 yaml 重建模型并加载原始权重，剪枝结构被悄悄丢弃 | 手动构造 `DetectionTrainer` 后直接赋值 `trainer.model` |
| `optimizer='auto'` 忽略 `lr0` 改用 AdamW | 显式 `optimizer='SGD', lr0=0.01` |
| Windows 默认 GBK 编码读 yaml 报错 | `read_text(encoding="utf-8")` |
